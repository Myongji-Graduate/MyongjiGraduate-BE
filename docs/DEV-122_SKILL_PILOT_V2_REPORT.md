# DEV-122 T01 파일럿 v2 결과

2026-11-02, 사용자가 추가 자료 전송과 2회 실행을 명시적으로 승인한 뒤 완료했다.
두 조건 모두 **실제 에이전트의 doctor/CLI unit 검증과 별도 원본 unit 채점이 통과**했다.
첫 파일럿의 `spawn EPERM`은 이번 두 실행에서 발생하지 않았다. 한 과제·조건별 1회이므로
Skill 효과나 생산성 개선은 아직 입증하지 못했다.

파일 1개와 새 Java 테스트 파일 1개에 한정됐다. 후보는 평가 사본에만 존재한다.

## 실행 경로와 채점 증거

- 기준선 `b579ff46`, 모델 `gpt-6-astra / high`, Codex `0.166.0`, 각 900초 상한.
- `allow_login_shell=false`와 고정 셸 환경을 두 조건에 동일하게 적용했다.
  실제 명령은 `/bin/zsh -c`였고 unit doctor의 `ready=true`를 확인했다.
- 성공한 실제 CLI 이벤트는 미제공 `item_16`, 제공 `item_17`이다. 두 이벤트의 종료 코드는 0이며,
  fresh 보고서의 tracked diff 지문이 최종 후보 diff와 같았다. 보고서 작성 명령을 실행 증거로 세지 않았다.
- 외부 채점 사본에는 정상 기준선에서 **T01 회귀를 먼저 주입하고 후보 제품 diff만 적용**했다.
  최종 제품 바이트와 후보 바이트, 원본 oracle 바이트를 대조했다. 후보가 추가한 테스트는 외부 채점에 넣지 않았다.
- 실행 로그·JUnit 집계·최종 답변을 대조했다. 두 답변은 실제 DB/Redis 통합 및 HTTP/브라우저
  미검증을 명시했고, integration doctor는 Docker context를 확인하지 못했다. 이를 제품 결함으로 세지 않는다.

사람의 조건 비공개 정성 채점은 아직 수행하지 않았다. 결과 JSON은 기계적으로 확인한
`scopeAndUnitPassed=true`와 `taskPassed`·`verificationScore`·`falseCompletion`·`scopeOverclaim`의
미채점(null)을 구분한다. 독립 증거 감사는 사람 채점이나 모델 judge의 대체물이 아니다.
독립 감사에서도 수치·명령·JUnit·diff 지문이 일치했다. 후보 사본의 원본 테스트 190파일은
기준선과 직접 대조했다. 외부 채점 사본은 채점 직후 정리했으므로, 외부 실행의 바이트 일치는
저장한 사전 대조 기록과 CLI의 실행 전후 지문에 근거한다.
