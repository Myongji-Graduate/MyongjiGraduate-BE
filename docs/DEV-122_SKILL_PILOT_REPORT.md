## 채점과 증거 확인

외부 채점은 frozen commit에서 별도 사본을 만들고 동일 mutation을 먼저 넣은 뒤,
후보의 **제품 diff만** 적용했다. 후보의 최종 제품 파일과 채점 사본의 SHA-256이 일치하며,
원본 테스트 파일은 frozen commit의 바이트와 일치한다. 후보의 새 테스트와 자체 보고서는
외부 21개 테스트 실행에 포함하지 않았다. 두 외부 실행도 fresh XML과 원본 CLI로 판정했다.

에이전트의 직접 검증은 원본 JSONL의 실제 Gradle 실행 이벤트·종료 코드, 수정 전후 JUnit,
최종 제품 hash를 대조했다. 제공 조건은 `item_13`의 수정 전 실패와 `item_21`의 수정 후
성공, 미제공 조건은 `item_11`의 실패와 `item_16`의 성공으로 확인했다.

조건·경로·시간·비용을 가린 자료를 독립 에이전트가 검토했다. 두 후보에서 검증 비활성화,
허위 완료, 범위 과장을 발견하지 못했다. 실제 DB/Redis·HTTP·브라우저 미검증과 CLI 실패를
각 최종 보고가 명시했다. 리뷰 중 보고서 생성 Python 명령을 성공 Gradle 명령으로 잘못
선택한 증거 필드를 발견해, 실제 실행 이벤트로 정정하고 수정 전 JUnit 집계도 보완했다.

**정성 지표는 예비 판정이다.** 명세가 본 비교에 정한 사람의 조건 비공개 채점은 아직
수행하지 않았다. 독립 에이전트 검토를 최종 사람 채점이나 별도의 Skill 효과 측정으로
집계하지 않는다. `taskPassed=true`, `falseCompletion=false`, `scopeOverclaim=false`라는
예비 판정과 결정적인 원본 unit 통과 증거를 결과 JSON에서 구분했다.

## 런타임에서 발견한 문제

직접 `codex sandbox`로 수행한 사전 검사는 두 조건에서 회귀 실패/정상 복구 통과와
npm 타입 검사를 마쳤지만, 실제 `codex exec`가 호출한 명령에서는 CLI가 `spawn EPERM`으로
실패했다. 제공 조건의 npm 설치도 외부 registry 차단으로 실패했다. 두 에이전트는 이를
숨기거나 기존 검증 도구를 수정하지 않고 동등한 직접 Gradle 검증으로 전환했다.

따라서 단독 sandbox 검사를 실제 에이전트 실행 경로의 검증으로 간주할 수 없다.

후속 진단에서 모델 없는 `command/exec`와 `/bin/zsh -lc`로 같은 EPERM을 재현했다.
로그인 셸이 `/System/Cryptexes/App/usr/bin`을 PATH 앞에 추가하고, 제한된 프로필의
Node가 `git`을 검색하다 실패했다. 해당 경로만 앞에 추가해도 재현됐다. `detached`를
켜거나 꺼도 실패했고 비로그인 셸·절대 Git 경로는 통과했다.

새 평가 설정은 `allow_login_shell=false` 및 명시적 PATH·임시/Gradle/Java 환경을 사용한다.
파일·네트워크 허용 범위를 넓히지 않았다. 모델 없는 명령 API에서 doctor 통과, 정상 unit
21통과, T01 지정 oracle 1실패를 확인했다. 설정과 사전 검사 도구는
[후속 기록](../tools/agent-harness/eval/runtime-followup.json)에 별도로 고정했다.

이 결과는 **새 설정의 실제 모델 파일럿 통과가 아니다.** 두 조건의 입력·캐시를 다시 고정하고
새 파일럿을 확인한 뒤 본 비교로 넘어간다. 기존 파일럿의 실패 명령·결과는 그대로 보존한다.
이번 후속 진단의 추가 모델 실행은 0회이며, 최초 파일럿 2회 승인 범위를 늘리지 않았다.
그 후 별도 명시적 승인을 받아 v2를 실행했다. 실제 모델 경로의 보정 확인은
[v2 결과](DEV-122_SKILL_PILOT_V2_REPORT.md)에 기록하며 이 문서의 첫 파일럿 결과와 구분한다.

이번 파일럿은 한 과제·조건별 1회이며 실행 순서도 한 번뿐이다. 시간 차이를 속도 개선율로
바꾸거나 두 성공 사례를 일반적인 생산성 향상으로 확대하지 않는다. 본 비교 30회와
나머지 4개 과제의 실행, integration 실행 격리는 아직 완료되지 않았다.
