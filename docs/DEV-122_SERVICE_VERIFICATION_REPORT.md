# DEV-122 — 서비스 단위 검증에 일상 리뷰 적용

2026-11-03. 과목 추가·삭제 서비스의 기존 단위 테스트를 보강해 실제 개발 변경을
`mju-verify` → CLI 검증 → 선택 변경의 독립 리뷰로 넘긴다.

## 변경과 완료 조건

기존 추가 테스트는 사용자 조회를 stub하지 않아 저장 과목에 null 사용자가 들어가도 통과했고,
학점 재계산 mock을 테스트 본문에서 직접 호출해 서비스가 재계산했는지 확인하지 못했다.
이 호출을 제거하고 실제 저장 인자의 사용자·과목과 저장 후 재계산 순서를 검사한다.

삭제 성공에서도 잠금·조회·삭제·재계산 순서를 확인한다. 사용자의 목록 밖 ID, 저장 실패,
삭제 실패에서는 삭제/재계산 부작용이 발생하지 않는지 검사한다. 서비스 구현은 변경하지 않는다.

완료 조건은 기존 네 클래스의 fresh unit 실행, 관련 로컬 CI 검사, 선택 파일과 근거의 독립 리뷰다.
DB rollback·실제 학점 값·HTTP·브라우저 동작은 이 mock 단위 변경의 완료 조건에 포함하지 않는다.

## 실행과 리뷰

| 검사 | 이번 결과 |
| --- | --- |
| CLI `takenlecture-unit --offline` | 24개 통과, 실패·오류·skip 0. 삭제 4·추가 2·조회 3·캐시 15 |
| 하네스 TypeScript 빌드·자체 검사 | 23개 통과 |
| 모델 없는 평가 보호 검사 | 46개 통과 |
| 일상 리뷰 묶음 검사 | 12개 통과 |
| 독립 모델 리뷰 | 12개 선택 파일, 1패스, 지적 0개. 모델 ID 미확인, 사람 확인 아님 |
| 리뷰 입력·현재 상태 검사 | 인용/구조 검증 통과, 선택 snapshot·연결한 tracked 지문 모두 현재와 일치 |
| 스킬 정적 검사 | bundled validator 통과 |

서비스 unit는 기존 21개에 실패 경로 3개를 더한 결과다. 고정 테스트 수가 아니라
이번 JUnit의 실제 클래스·testcase 집계를 대조했다. 실행 전후 선택 파일 지문이 같았으며,
선택한 테스트가 tracked 상태여서 이번 CLI report의 변경 지문과도 대조할 수 있었다.
나머지 검사는 GitHub workflow의 로컬 검사 명령을 실행한 결과이며 원격 CI 실행으로 표시하지 않는다.

관련 구현·포트·도메인·테스트·기능 지도 12개와 이번 unit report/JUnit을 선택 리뷰 입력으로 만들었다.
`build/agent-harness/dev122-service-verification/`에 명령·로그·선택 snapshot을 보존한다.
별도 읽기 context의 리뷰어는 입력만 검토하고 결과 JSON 하나만 작성했다.
테스트를 독립 재실행한 것은 아니며, 원본 workspace 접근을 막는 OS sandbox를 사용한 것도 아니다.
최종 [기계 판독 결과](../tools/agent-harness/review/service-verification-result.json)와 증거의
`final-checks.json`에 검증 상태를 기록했다. 기존 T04 증거 242개도 보존 hash와 모두 일치한다.

## 해석과 남은 경계

이번 변경은 서비스 구현 수정 사례가 아니라 실제 서비스 테스트 개선에 하네스를 적용한 사례다.
검사 통과는 mock 인자·호출·순서의 계약이며 DB commit/rollback이나 실제 계산된 학점의 정확성을
증명하지 않는다. DB 통합·HTTP·UI를 이번 단계에서 다시 실행하지 않았다.
실학생 스냅샷·DB는 사용하지 않았으며 새 코딩 파일럿·30회 비교도 실행하지 않았다.

원격 CI는 현재 미커밋 코드를 게시한 뒤 별도로 확인해야 한다. 커밋·푸시·배포는 하지 않았다.
실제 서비스 변경에서 사용자의 사용성 피드백과 바뀐 스킬 안내의 효과도 아직 측정하지 않았다.
